§ B — Local environment

The dev box.

  • Python 3.13. Required by splunk-sdk-python v3.0.0. Install via pyenv or your platform's installer. Verify with python --version.
  • Project skeleton. Create pyproject.toml with Python 3.13 requirement, Apache 2.0 license metadata, and the dependency list. See structure below.
  • splunk-sdk-python v3.0.0. Install with pip install splunk-sdk-python==3.0.0. Verify splunklib.ai imports cleanly — if it doesn't, you're on an older SDK.
  • Splunk MCP Server v1.1.2. Download from Splunkbase app 7931. Install on your local Splunk Enterprise instance. Generate a bearer token from inside the MCP Server app — the legacy Settings → Tokens path was deprecated in v1.0.0 and won't work.
  • MCP user role. Create a dedicated non-system user with the mcp_user role and mcp_tool_execute capability. splunklib.ai PR #753 explicitly forbids running agents as the system user.
  • Ollama (local LLM fallback). Install from ollama.com. Pull llama3.1:8b-instruct. This is your offline fallback for CLI and GitHub Action modes since Hosted Models are Splunk Cloud-only.
  • Test the connection. Write a 20-line script that authenticates to your local Splunk via the MCP Server, calls splunk_get_info, and prints the response. If this fails, fix it now — every subsequent step depends on this working.

§ C — The Master Skill

The single document your AI agent reads first.

Save the block below as skill.md at the root of your repo. At the start of every AI coding session — whether you're using Claude Code, Cursor, or any other assistant — paste this file into the context first. It encodes everything an agent needs to write code that fits the project: tech stack, version-pinned dependencies, the SDK's two breaking-change gotchas, the Splunk platform's RBAC and Cloud-only constraints, file structure conventions, code style, output conventions, and the timeline pressure.

Update this skill whenever a new constraint surfaces during the build. Versioned in git, it's the agent's persistent memory across sessions.

skill.md — paste into AI coding agent context at session start
# Brief — Master Skill ## Project context You are helping build **Brief**, an AI agent that audits Splunk apps for AI-agent-readiness. It scans `.conf` metadata, uses the Splunk AI Assistant for SPL to understand each saved search, generates rich semantic descriptions with Foundation-Sec or gpt-oss-20b, and emits three artifacts: an agent-readiness score, a unified-diff PR, and an MCP manifest. The full spec is in `docs/brief-spec.html`. Read §03 (pipeline) and §06 (Splunk AI stack) before writing any agent code. This is a hackathon submission. Deadline: **June 15, 2026, 09:00 PDT** (submit by EOD June 14). Track: **Platform & Developer Experience**. Bonus targets: Best Use of Developer Tools, MCP Server, and Hosted Models (stackable). ## Tech stack — pinned versions - Python **3.13** — required by splunk-sdk-python v3.0.0 - `splunk-sdk-python` **3.0.0** — released May 12, 2026 - Splunk MCP Server **v1.1.2** — Splunkbase app 7931 - Splunk Hosted Models: **Foundation-Sec-1.1-8B-Instruct** (security apps), **gpt-oss-20b** (general apps) - Splunk AI Assistant for SPL **v1.4.0+** — exposes `saia_explain_spl` as MCP tool - AppInspect — for safety validation - Local fallback: **Ollama** with `llama3.1:8b-instruct` for offline modes ## Critical SDK pitfalls — get these wrong, agent loops break silently 1. Agent state is `Agent.messages`, **not** `Agent.response`. Renamed in PR #743. Older tutorials show `.response` — those are wrong for v3.0.0. 2. Token/step/timeout middleware lives in `splunklib.ai.limits`, **not** `splunklib.ai.hooks`. Moved in PR #759. Importing from `.hooks` will fail. 3. `id` is required (non-nullable) for tool, subagent, and output calls. PR #724. Generate UUIDs explicitly. 4. Default AgentLimits: max_tokens=200000, max_steps=100, timeout=600s. Override for Brief's longer audit sessions if needed. 5. Structured output uses Pydantic models passed to `Agent.respond()` — schema enforcement is automatic but bad outputs auto-retry; don't catch retries as errors. ## Critical Splunk pitfalls 1. MCP Server bearer tokens must be generated **from inside the MCP Server app**. The legacy Settings → Tokens path was deprecated in v1.0.0 — tokens from there will be rejected. 2. **Do not use OAuth 2.1.** It's a closed Cloud-only preview, requires Twix 10.3.2512.X, and needs ~1 week of Splunk Identity Service team coordination. Static encrypted bearer tokens are the supported hackathon path. 3. MCP guardrails for `splunk_run_query`: ≤60s runtime, ≤1000 events, no destructive SPL (no `| delete`, `| outputlookup` to destructive paths, etc.). Brief's safety analyzer enforces these statically before any search is flagged as agent-callable. 4. Required MCP role: `mcp_user` with `mcp_tool_execute` capability. For Brief's Splunk app deployment shape doing cross-app enumeration: `sc_admin` with `mcp_tool_admin`. 5. The agent must NOT run as the system user — PR #753 explicitly forbids this. Create a dedicated user. 6. **Splunk Hosted Models are Cloud-only.** They cannot be reached from offline development. CLI and GitHub Action modes use the local Ollama adapter. Live mode (Brief running inside Splunk Cloud as a Splunk app) uses Hosted Models. ## File structure ``` brief/ ├── pyproject.toml ├── src/brief/ │ ├── __init__.py │ ├── agent.py # The splunklib.ai Agent │ ├── scanner/ # Stage 1 │ │ ├── conf_parser.py │ │ ├── xml_parser.py │ │ ├── safety.py │ │ └── signals.py │ ├── spl/ # Stage 2 │ │ ├── macro_expander.py │ │ └── explainer.py # saia_explain_spl wrapper │ ├── generator/ # Stage 3 │ │ ├── schema.py # Pydantic GeneratedDescription │ │ ├── hosted.py # Splunk Hosted Models adapter │ │ └── local.py # Ollama fallback │ ├── scoring/ # Part of Stage 4 │ │ └── score.py │ ├── emit/ # Stage 4 │ │ ├── diff.py │ │ ├── manifest.py │ │ └── report.py │ ├── cli.py # Entry point (typer) │ └── app_splunk/ # Splunk app deployment shape ├── action.yml # GitHub Action manifest ├── Dockerfile # For Action container ├── tests/fixtures/ # Sample Splunk apps ├── docs/ # brief-spec.html + step-*.html └── architecture_diagram.png # Required by hackathon rules ``` ## Code conventions - Type hints everywhere — Python 3.13 native syntax (`list[str]`, `dict[K, V]`, `X | Y`) - Pydantic for cross-module data models; dataclasses for internal-only - `pathlib.Path` always; never `os.path` string concatenation - `logging` with `structlog` adapter, not `print()` - `async` for: agent calls, MCP calls, parallel SPL explanation in batch mode - Module size: prefer many small files over one large module - Docstrings: every public function. Examples in the docstring where non-obvious. ## Pydantic schema — the generation contract ```python class GeneratedDescription(BaseModel): description: str = Field(min_length=80, max_length=240) primary_use_case: str output_fields: list[str] mitre_techniques: list[str] | None = None # security apps only estimated_runtime: Literal["fast", "medium", "slow"] suitable_for_agent: bool ``` Foundation-Sec is asked to produce descriptions that: - Lead with a verb ("Returns", "Counts", "Detects") - Name specific event IDs, sourcetypes, or indexes that appear in the SPL - State the canonical use case ("Use for credential stuffing investigations") - Include MITRE technique IDs in a separate field, never in prose - Avoid hedging ("might", "possibly", "could be useful for") ## Testing approach - `pytest` for everything - 2–3 sample Splunk apps committed to `tests/fixtures/` - Mock Splunk Hosted Models with the local Ollama adapter — tests run offline - Snapshot test the diff PR outputs so generation changes are reviewable in git - Integration test: end-to-end CLI run on a fixture app, assert score > 80% ## Output conventions - All artifacts go to a configurable `--output` directory - Default structure: `report.html`, `score.json`, `descriptions.diff`, `mcp_manifest.yaml` - **Never modify input files in place.** Brief proposes via diff; humans approve via PR merge. ## Output: MCP manifest schema ```yaml app: TA_security_monitoring tools: - name: get_failed_auth_24h saved_search: get_failed_auth_24h description: | Returns count of failed Linux SSH logins (event 4625) by user and source IP in the last 24h. Use for credential stuffing. output_fields: [user, src_ip, count] mitre_techniques: [T1110.001, T1078] rbac_role: mcp_user estimated_runtime: fast ``` ## Hackathon-required artifacts - Public GitHub repo with detectable OSI license (Apache 2.0 chosen) - README with setup instructions and dependency list - Demo video < 3 minutes, public on YouTube or Vimeo - File at repo root named exactly `architecture_diagram.png` (or `.md` or `.pdf`) ## Timeline awareness - 28 days total: May 18 → June 15, 2026 - Submit by **EOD June 14**, never trust the portal on deadline day - Step 09 (demo + submission) reserves Week 4 — protect that buffer - Splunk Enterprise trial expires July 17 (winners day); Developer License extends to 6 months — apply within first 7 days - Splunk Cloud trial provisioning takes 24–48h; apply Day 1
