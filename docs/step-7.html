Step Seven.

Brief as a Splunk app — installable, schedulable, and observable from a dashboard alongside the apps it audits.

§ Context

Where we are.

The CLI is the developer workflow shape. Step 07 builds the internal compliance tool shape: Brief packaged as a real Splunk app, installable on a Splunk Cloud or Enterprise instance, scheduled to run periodically, and exposing a dashboard that shows the agent-readiness score for every other installed app on the deployment.

This deployment shape unlocks the Hosted Models path — when Brief runs inside Splunk Cloud, Foundation-Sec and gpt-oss-20b become natively reachable. It's the strongest demo of the project's Splunk-platform fit.

§ Goal

What Step 07 delivers.

  • A complete Splunk app structure under src/brief/app_splunk/
  • app.manifest + default/app.conf with proper metadata
  • A scheduled saved search that triggers a Brief audit weekly
  • A Splunk dashboard showing readiness scores per installed app, with drill-down
  • AppInspect validation passing without errors
  • The app packaged as brief-app-0.1.0.spl ready for Splunkbase submission
Read `skill.md` first. Critical: for cross-app enumeration, the service account running Brief inside Splunk needs sc_admin role with mcp_tool_admin capability — not just mcp_user. Document this clearly in the install instructions. Build the Splunk app deployment shape. Files to create src/brief/app_splunk/app.manifest ```json { "schemaVersion": "2.0.0", "info": { "title": "Brief — Agent-Readiness Auditor", "id": { "group": null, "name": "brief", "version": "0.1.0" }, "author": [{"name": "", "email": ""}], "releaseDate": "2026-06-07", "description": "Audits installed Splunk apps for AI-agent-readiness. Generates semantic descriptions, agent-readiness scores, and MCP manifests using Foundation-Sec and gpt-oss-20b via Splunk Hosted Models.", "classification": { "intendedAudience": "Developers, Administrators", "categories": ["AI/ML", "Utilities", "Developer Tools"], "developmentStatus": "Beta" }, "commonInformationModels": {}, "license": { "name": "Apache-2.0", "uri": "https://www.apache.org/licenses/LICENSE-2.0" } }, "dependencies": null, "tasks": [], "inputGroups": {}, "incompatibleApps": {}, "platformRequirements": { "splunk": { "Enterprise": "9.0+", "CloudPlatform": "*" } } } ``` src/brief/app_splunk/default/app.conf Standard app.conf with `is_visible = 1`, `state = enabled`, proper `[ui]` block with label and description, `[launcher]` block. Reference any other modern Splunk app's app.conf as a template. src/brief/app_splunk/default/savedsearches.conf A scheduled audit search. The "search" is a single custom command call that triggers the Brief agent: ```ini [brief_weekly_audit] search = | brief_audit mode=live dispatch.earliest_time = -7d dispatch.latest_time = now cron_schedule = 0 3 * * 0 enableSched = 1 description = Brief — weekly cross-app agent-readiness audit ``` src/brief/app_splunk/bin/brief_audit.py A Splunk custom search command (using `splunklib.searchcommands.GeneratingCommand`) that wraps the same `audit_app()` orchestrator from Step 04. Iterates over installed apps in `$SPLUNK_HOME/etc/apps/`, runs the agent in live mode, writes results to a Brief-internal index (`brief_scores`) for the dashboard to read. src/brief/app_splunk/default/data/ui/views/brief_dashboard.xml Splunk Simple XML dashboard with these panels: 1. Headline panel — aggregate readiness score across all installed apps (single value, large) 2. App ranking table — every installed app with its score, sortable. Drill down to a per-app detail dashboard 3. Trend over time — line chart of overall readiness over the last 90 days (requires multiple historical scans) 4. Worst-performers panel — top 5 apps with the lowest scores, with their dominant issues (missing descriptions, tautologies, safety violations) 5. Coverage breakdown — stacked bar showing presence / quality / coverage / safety contribution per app Style: use Splunk's modern dashboard CSS. Don't over-customize — judges value clean, native-looking dashboards. src/brief/app_splunk/default/data/ui/views/brief_app_detail.xml Per-app drilldown showing every saved search with its current score, generated description (if any), and a link to the diff PR / MCP manifest stored as KV-store entries. src/brief/app_splunk/metadata/default.meta Standard meta file. Read access to `role_user`, write to `role_admin`. The dashboards should be visible to anyone who can read the Brief app. src/brief/app_splunk/README.md Brief-specific install instructions: - Required role for the service account: sc_admin + mcp_tool_admin capability - Splunk Cloud only (Foundation-Sec / Hosted Models requirement) - Splunk Enterprise 9.0+ required - Manual token generation step from inside the MCP Server app (NOT Settings → Tokens) - Walk through the dashboards once installed AppInspect validation Run splunk-appinspect inspect src/brief/app_splunk/ after each significant change. Fix every error (warnings are acceptable but document them). The hackathon expects clean AppInspect passes. Packaging A simple script in scripts/package-app.sh: ```bash cd src/brief/app_splunk/ tar -czf ../../../brief-app-0.1.0.spl --exclude='__pycache__' --exclude='*.pyc' . ``` Final artifact: brief-app-0.1.0.spl at repo root, ready to upload to a Splunk instance or attach to a Splunkbase submission. Constraints - The custom search command must complete within Splunk's default 5-minute search timeout, OR run as a scheduled report (not interactive) - The Brief app must not interfere with audited apps — read-only access to other apps' filesystems - Never commit a token to the app — admins configure it via the app setup screen - Compliance with Splunk app review standards: no eval'd strings, no unsafe imports, no hardcoded paths Testing - Install the .spl file on your local Splunk Enterprise — verify it loads without errors - Run the dashboard manually — verify panels populate - Trigger the scheduled search manually — verify it runs end-to-end and writes to the brief_scores index - AppInspect passes with zero fatal errors Acceptance - The .spl file installs cleanly on your local Splunk Enterprise - The Brief dashboard shows readiness scores for at least 3 installed apps - AppInspect output is clean - Install instructions in the app's README are accurate enough that a stranger could install it
