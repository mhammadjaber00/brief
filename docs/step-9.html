This step is mostly content production, not code. The prompt below is a checklist for you (the human), not for an AI coding agent. Day 1 — Pick the demo target Browse Splunkbase and shortlist 3 TAs that meet ALL of: - Modest size (under 50 saved searches — keeps demo runtime tight) - Visibly sparse descriptions when you inspect savedsearches.conf - Security or popular-tech category (so Foundation-Sec applies and audience cares) - Open license you're comfortable showing on camera Run brief scan against each. The one with the worst readiness score AND the most visually compelling SPL (clear MITRE-relevant searches like failed-auth detection) is your demo target. Note the baseline score. Suggested candidates to inspect (verify still on Splunkbase): - Older TAs for common security tools (firewall, IDS, EDR vendors) - Any TA that hasn't been updated since 2023 Run a full brief audit on the chosen target. Inspect the diff and HTML report. If the generated descriptions look bad, this is your last chance to iterate on prompts. Day 2 — Architecture diagram The hackathon rules require a file at repo root named EXACTLY architecture_diagram.png (or .md or .pdf). Replace the placeholder from Step 01. The diagram should show: - Three deployment shapes (CLI, Splunk app, GitHub Action) on the left - The Brief Agent (splunklib.ai) in the center - The Splunk AI tools used (MCP Server, AI Assistant for SPL, Hosted Models) on the right - The four output artifacts at the bottom Tools that work: draw.io / Excalidraw / Figma / OmniGraffle. Export at high DPI (at least 1500px wide). Match the visual language of brief-spec.html if you have time — warm off-white, sage / amber accents. Day 4 — Demo video recording (under 3 minutes, hard limit) The video is what wins or loses the hackathon. Script: 0:00–0:15 — Opening. On-screen text: "In April 2026, Splunk told developers their apps need to be agent-ready." Cut to the April 2026 blog post screenshot. Voiceover: "Splunk said it. Then offered free 1-on-1 consulting to fix it. With 2,800 apps on Splunkbase, that doesn't scale." 0:15–0:35 — The problem made tangible. Show the demo target TA's savedsearches.conf. Highlight an undescribed saved search. Voiceover: "This saved search detects credential stuffing across SSH. An AI agent looking at this file has no idea what it does. Description fields are empty. Macros are inscrutable. To the agent, this app is invisible." 0:35–0:50 — Introduce Brief. Voiceover: "Brief is an AI agent that fixes this. Built on splunklib.ai — released six days before this hackathon — it scans the app, uses Splunk's own AI Assistant to understand each SPL search, then uses Foundation-Sec to generate descriptions an agent can actually call." 0:50–1:50 — The transformation moment. This is your single most important segment. Run brief audit against the demo TA. Cut to the HTML report. Show: - Before: readiness score X% (e.g., 14%) - After: projected Y% (e.g., 92%) - Zoom in on one saved search: before was empty / tautological; after has full description, output fields, AND MITRE T1110.001 tag The MITRE tag is the magic. It demonstrates Foundation-Sec doing something a general model couldn't. Make it visually pop. 1:50–2:20 — Show the three deployment shapes. Quick cuts: CLI in terminal, Splunk app dashboard rendering scores across 5 installed apps, GitHub Action posting a PR comment. 2:20–2:40 — The diff PR. Cut to GitHub. Show the auto-opened PR with the description changes. Voiceover: "Brief never overwrites. Every change is a unified diff in a pull request — humans approve before merge." 2:40–3:00 — Outro. On-screen: "Brief. Built for the Splunk Agentic Ops Hackathon. Apache 2.0. github.com/<you>/brief." End with a Splunk MCP Server logo crossfade. Record screen with OBS or Loom. Use a clean terminal theme. Punch in volume normalization on the voiceover. Upload to YouTube as Public (NOT Unlisted — the hackathon rules require public).
