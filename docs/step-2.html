Step Two.

The scanner — parse a Splunk app and quantify what an agent could and couldn't see.

§ Context

Where we are.

Accounts provisioned, environment ready, MCP Server reachable, master skill committed. Step 02 builds Stage 1 of the pipeline: the parsing and signal-extraction layer.

No LLM calls yet — this step is deterministic parsing and static analysis. The output is structured data describing every scannable object in a target Splunk app, ready to feed into the SPL-comprehension stage in Step 03.

§ Goal

What Step 02 delivers.

  • A working scan_app(path) function that reads a Splunk app folder and returns a structured report
  • Parsers for .conf files (configparser-based) and dashboard XML (lxml-based)
  • A static SPL safety analyzer enforcing MCP guardrails (runtime, event volume, destructive commands)
  • Per-object signal extraction: presence, description text, safety verdict, raw definition
  • Per-file coverage rollups
  • An end-to-end test running on a real Splunkbase TA committed to tests/fixtures/
  • A CLI smoke test: brief scan PATH prints a summary table
Read `skill.md` first. Then build Brief's scanner — Stage 1 of the pipeline. No LLM calls in this step; this is deterministic parsing and static analysis only. Files to create src/brief/scanner/models.py Pydantic models for everything the scanner produces: - `ObjectSignals(name, object_type, description_present, description_text, quality_score=None, safety, raw_definition, file_origin)` - `SafetyReport(safe: bool, violations: list[str], warnings: list[str])` - `FileCoverage(file_name, total_objects, described_count, coverage_pct)` - `EmbeddedSearch(dashboard, panel, query)` - `AppScanReport(app_name, app_version, app_description, objects, file_coverage, embedded_dashboard_searches)` - `object_type` is a Literal of "savedsearch" | "macro" | "eventtype" | "tag" | "transform" | "command" src/brief/scanner/conf_parser.py A `ConfParser` class wrapping Python's `configparser`, with these adaptations for Splunk: - Handle the `default/` + `local/` layered config pattern — local stanzas override default at the key level (not stanza level) - Stanza inheritance via the implicit `[default]` block - Multi-line values (continuation with backslash + indented next line) - Comments start with `#` - Return `dict[stanza_name, dict[key, value]]` Files this module should be able to read: `app.conf`, `app.manifest`, `savedsearches.conf`, `macros.conf`, `eventtypes.conf`, `tags.conf`, `transforms.conf`, `commands.conf`. Public method: `parse_file(path: Path) -> dict`. src/brief/scanner/xml_parser.py Uses `lxml` to extract searches from dashboard XML files in `data/ui/views/*.xml`. Public function: `extract_dashboard_searches(views_dir: Path) -> list[EmbeddedSearch]`. Handle both Simple XML (`` elements) and Studio dashboards (JSON-in-XML). src/brief/scanner/safety.py Static SPL guardrail analyzer. Public function: `analyze_spl(spl: str) -> SafetyReport`. Checks: - Destructive commands — regex for `| delete`, `| outputlookup` (flag as warning unless target is in a known-safe lookup list), `| sendalert`, `| script`, `| outputtext`. Each match becomes a `violations` entry. - Runtime hints — heuristic: if SPL contains `| join`, `| append`, or `earliest=-30d@d` without `| head N`, flag as `warnings` (probably exceeds 60s). - Event volume — if SPL has no terminal aggregation (`| stats`, `| chart`, `| timechart`, `| top`, `| rare`) and no `| head N`, flag as warning (probably exceeds 1000 events). - Index breadth — `index=*` without further filtering is a warning. The function returns `SafetyReport(safe=len(violations)==0, violations, warnings)`. Warnings don't disqualify but feed into the safety signal score in Step 05. src/brief/scanner/signals.py Per-object signal extraction. For each saved search, macro, etc., produce an `ObjectSignals`. Quality is left as `None` here — Stage 3 fills it. Key rules: - `description_present` is True only if the description key exists AND its value is > 10 chars after stripping whitespace - `raw_definition` holds the `search = ...` value for saved searches, the `definition = ...` value for macros, etc. - `safety` comes from `analyze_spl()` for objects with SPL content src/brief/scanner/__init__.py Public entry point: `scan_app(path: Path) -> AppScanReport`. Orchestrates: 1. Read `app.manifest` and `app.conf` for app identity 2. Walk `default/` and `local/` for all .conf files; merge with local-overrides-default 3. Walk `data/ui/views/` for dashboards 4. Compute signals per object 5. Roll up file coverage 6. Return the report src/brief/cli.py Minimal `typer` app exposing `brief scan PATH [--output DIR]`. For now it just runs `scan_app()` and prints a summary table using `rich`. CLI polish happens in Step 06. Constraints - DO NOT call any LLMs in this step - DO NOT generate descriptions yet - DO NOT touch the live MCP code path yet — offline filesystem only - Stay focused — Stages 2, 3, 4 come in subsequent steps.
