Step Six.

The CLI — the first of three deployment shapes, and the one your demo will run against.

§ Context

Where we are.

The pipeline works end-to-end via audit_app(). A minimal brief scan stub exists from Step 02. Step 06 polishes that into the production CLI: clean commands, configuration, progress feedback, env-var-based secrets, and a tested end-to-end run on a real Splunkbase TA.

The CLI is the deployment shape your 3-minute demo video will most likely feature — it's the fastest path to a compelling "before vs after" visual. Treat its UX accordingly.

§ Goal

What Step 06 delivers.

  • Two primary commands: brief scan PATH (Stage 1 only, fast, no LLM) and brief audit PATH (full pipeline, all four stages)
  • A --mode live|offline flag controlling whether the agent uses Hosted Models or Ollama
  • Configuration loading: env vars → .env file → CLI flags (later wins)
  • Rich progress indicators during long-running phases (each saved search explained / generated is one tick)
  • An end-to-end run on a real Splunkbase TA, with the four output artifacts inspected by hand
Read `skill.md` first. Polish the CLI into Brief's primary deployment shape. Files to update src/brief/cli.py Replace the Step 02 stub with a full typer app: ```python import typer from pathlib import Path from typing import Annotated app = typer.Typer(name="brief", help="Audit Splunk apps for AI-agent-readiness.") @app.command() def scan( path: Annotated[Path, typer.Argument(help="Path to a Splunk app folder")], output: Annotated[Path, typer.Option("--output", "-o")] = Path("./brief-output"), format: Annotated[str, typer.Option("--format", "-f")] = "table", # table | json ): """Stage 1 only — fast structural audit, no LLM calls.""" ... @app.command() def audit( path: Annotated[Path, typer.Argument(help="Path to a Splunk app folder")], output: Annotated[Path, typer.Option("--output", "-o")] = Path("./brief-output"), mode: Annotated[str, typer.Option("--mode")] = "offline", # offline | live app_class: Annotated[str, typer.Option("--app-class")] = "auto", # auto | security | general model: Annotated[str | None, typer.Option("--model")] = None, # override default model verbose: Annotated[bool, typer.Option("--verbose", "-v")] = False, ): """Full audit — scan, explain, generate, score, emit.""" ... ``` Both commands must: - Validate the input path exists and looks like a Splunk app (contains `default/` or `local/` with `.conf` files) - Resolve configuration (env → `.env` → flags) - Render a rich progress bar for the long-running stages - On completion, print a summary block with: overall score, file locations of the four output artifacts, and a one-line callout (e.g., "Open report.html to review") - Exit code 0 on success, 1 on partial failure (some descriptions couldn't be generated), 2 on full failure src/brief/config.py Centralized configuration loading. Use `pydantic-settings`: ```python class BriefConfig(BaseSettings): splunk_mcp_url: str | None = None splunk_mcp_token: SecretStr | None = None splunk_cloud_api_key: SecretStr | None = None # for Hosted Models ollama_url: str = "http://localhost:11434" ollama_model: str = "llama3.1:8b-instruct" output_dir: Path = Path("./brief-output") class Config: env_file = ".env" env_prefix = "BRIEF_" ``` Document the env vars in `README.md`: BRIEF_SPLUNK_MCP_URL, BRIEF_SPLUNK_MCP_TOKEN, etc. src/brief/cli_helpers.py Progress reporting helpers using `rich.progress`. One progress bar per stage with descriptive labels: "Parsing .conf files", "Explaining SPL (X of Y)", "Generating descriptions (X of Y)", "Emitting artifacts". End-to-end test Pick a real, modestly-sized Splunkbase TA (under 30 saved searches). Suggestions worth checking on Splunkbase: - Older TA-* technology add-ons with sparse descriptions - TAs that haven't been updated since pre-2024 (likely missing modern metadata) Download it, unpack into tests/fixtures/real-ta/, and run: ```bash brief audit tests/fixtures/real-ta/ --mode offline --verbose ``` Manually inspect: - The overall score in score.json - 5 generated descriptions in the diff — do they sound right? - The HTML report in a browser — does it look demo-ready? - The MCP manifest YAML — does it have the right shape? If any of these look off, that's the signal to iterate on prompts (in src/brief/generator/prompts.py) before moving to Step 07. Constraints - DO NOT hardcode any tokens or URLs in source - DO NOT log secrets, even at verbose level — Pydantic's SecretStr handles this automatically - The CLI should work with zero arguments beyond the path (sensible defaults for everything) - Live mode failing (e.g., MCP unreachable) should fall back to offline mode with a clear warning, not crash Acceptance - brief scan PATH runs in under 10 seconds on the real TA - brief audit PATH runs in under 5 minutes on the real TA in offline mode - The verbose flag produces useful trace output without leaking secrets - The end-to-end inspection on a real TA produces visually compelling before/after that you'd be comfortable putting in a demo video
